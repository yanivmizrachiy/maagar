# Scale Readiness — maagar

Updated: 2026-06-23

מסמך זה הוא מדריך בלבד. הוא אינו מקור כללים. הכללים המחייבים נמצאים רק ב־`RULES.md`.

## מצב נוכחי

- המאגר כבר עבר משלב קטן לשלב בינוני: 321 קבצים חיים באתר.
- האתר עדיין סטטי וללא backend.
- מקור הקבצים הפעילים: `metadata/index.json`.
- יש לפחות קובץ גדול מאוד: `חוברת.pdf` בגודל 97MB, ולכן הוא לא מתאים להטמעה רגילה בנייד.

## מדיניות גודל מומלצת

| גודל קובץ | המלצה |
|---|---|
| עד 5MB | אידיאלי לאתר |
| 5–15MB | קביל, עדיף לדחוס אם אפשר |
| 15–50MB | כבד; לשקול הורדה בלבד או גרסה דחוסה |
| מעל 50MB | לא להטמיע; הורדה בלבד / Releases / אחסון חיצוני |

## metadata/index.json

ב־321 קבצים עדיין אפשר לעבוד עם קובץ JSON אחד.

סף מומלץ לפיצול:

| מספר רשומות | המלצה |
|---|---|
| עד 500 | `metadata/index.json` אחד |
| 500–1000 | לשקול טעינה לפי שכבה |
| מעל 1000 | לפצל ל־`index-grade-7.json`, `index-grade-8.json`, `index-grade-9.json`, `index-high-school.json` |

## חיפוש

החיפוש בצד לקוח עדיין מתאים למאות קבצים.

כאשר המאגר יגיע לאלפי פריטים, לשקול:
- debounce לחיפוש.
- אינדקס חיפוש סטטי.
- Pagefind או פתרון static search דומה.

## סדר פעולות מומלץ עכשיו

1. לא להחליף ארכיטקטורה.
2. לא להכניס backend.
3. לסדר `topics` ו־metadata.
4. לטפל בקבצים כבדים.
5. לשמור על GitHub Pages כל עוד הביצועים סבירים.
